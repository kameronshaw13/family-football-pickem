# Family Pick'em audit — October 19, 2026

## Scope and source

This audit uses the GitHub repository connected to the live Vercel deployment (`kameronshaw13/family-football-pickem`, base commit `a3f1a1c`). The older local `family-football-pickem` folder does not contain the current Friends and basketball features and is not the deployment source. The audit covers the shared UI, login, board data, game schedules, odds, scores, test health, and read-only production checks. No production data was changed.

## Findings and fixes in this branch

| Priority | Finding | Fix |
| --- | --- | --- |
| High | The Supabase odds job is named `refresh-pickem-markets-5m` but actually runs at minute 50 once per hour. Current-week persisted lines can therefore lag an hour even while the UI polls quotes more often. | Prepare a 30-minute schedule for Tuesday–Friday open hours, with daily Sunday/Monday schedule passes; update the endpoint window and scheduler SQL. Production keeps its old cadence until both are deployed. |
| High | Football app data fetched only the first 1,000 game rows. The live database already has more than 1,000 CFB and NFL rows together, so late-season games could disappear. Locked picks had the same limit. | Bound the football query to the active season and page games and locked picks. Keep deterministic pagination for side bets. |
| High | Schedule discovery wrote provider spreads directly into game rows without going through spread freeze, odds snapshot, and saved-dog reconciliation logic. | Preserve spreads during schedule discovery and let the existing market pass apply those safeguards. |
| Medium | A moved football matchup could leave a stale old kickoff in the database because schedule identity lookup only scanned the previous day. One live Auburn–Ole Miss row appears to have an obsolete October 17 kickoff while the matchup is listed for October 31. | Include the previous 21 days when matching schedules and prefer ESPN event IDs; a later successful schedule pass can move the same row rather than duplicating it. Verify the affected game after rollout. |
| Medium | Missing ESPN scores could parse as zero, and one-sided college matching could attach another game's score. | Keep missing scores null and require both teams to match for college score and grading lookups. |
| Medium | Startup fallback could silently show cached app data for 24 hours after a request failure. Score and odds polling failures were also silent. | Limit startup cache fallback to 15 minutes; visibly label saved data and delayed score/market feeds after repeated failures. |
| Medium | The interface used small slab labels throughout and the login defaulted to account creation. | Apply a consistent system font, clearer contrast, spacing, focus states, controls, rows, standings, and login layout across all four groups. Default login to Sign in. |
| Low | CFB SRS ratings could oscillate on a small schedule; several tests described older behavior and the test runner could not resolve two source imports. | Dampen SRS iteration, stabilize Core rating rounding, repair imports, and align tests with current date and alternate-line display rules. |

## Production observations

- Supabase project `family-football-pickem` was active with 1,161 games and 143,654 odds snapshots at audit time. The latest odds snapshot was about six hours old when checked on October 19; snapshot time reflects a **changed line**, so it alone is not proof of scheduler failure.
- The results job is actually scheduled every five minutes. The client requests live scores every five seconds while active games are present and market quotes every 30 seconds while the board is visible. The prepared changes focus on persisted lines, matching, and honest failure states.
- An unauthenticated production login page was checked visually. A signed-in browser session and local production environment variables were unavailable, so authenticated end-to-end browser flows and measured API latency could not be verified. The app's build, lint, and automated suite cover source-level behavior.
- Supabase advisors reported tables with RLS enabled and no policies, plus public `pg_net` placement and several index suggestions. This app uses server-side database access; these warnings need a separate permissions and query-plan review before changing production policies or indexes. There is no evidence here that anonymous users can read the tables.

## Rollout and verification

1. Deploy the application commit from this branch.
2. Run `supabase/odds-cron.sql` in the live Supabase project. It replaces the misnamed hourly job with `refresh-pickem-markets-30m`. Do not run the SQL before deploying the matching endpoint window.
3. Verify `cron.job` has one active odds job at `20,50 * * * *`, inspect its HTTP response, and confirm odds snapshots or game lines advance when the provider changes them.
4. Check the Auburn–Ole Miss row after the next schedule pass, plus several college and NFL live/final scores and the final pages of games and locked picks.
5. Use a signed-in session to visually review Pick Board, Side Bets, My Card, Standings, and Settings on mobile and desktop. The login screens were checked at both widths.

Local verification for this branch: `npm run lint`, `npm test`, and `npm run build`.
